# 期末复习网站质量与验收

日期：2026 年 10 月 27 日。测试范围来自[需求说明](requirements.md)和[产品待办列表](product-backlog.md)。初始版本已完成账号、课程与局部技术探针自检，见[实际执行记录](records/initial-increment-20261027.md)。下列仅按已验证范围更新，代理自检不替代团队验收。

## 1 完成的定义

以下 DoD 为团队讨论的基线。实际团队审阅者尚未分配，不提前填写评审通过。

| 检查项 | 可验证依据 |
| --- | --- |
| 功能满足已选故事的验收标准 | 对应 TC 有实际结果，失败项有缺陷或修复记录 |
| 主流程能在目标环境运行 | 记录运行版本、启动步骤和完整演示结果 |
| 相关权限与异常行为正确 | 覆盖跨账号、非法输入、失败恢复及适用的重复请求场景 |
| 无阻断演示、越权、数据丢失等严重缺陷 | 缺陷列表中无未处理严重项；其他已知问题说明影响 |
| 改动经过检查或评审 | 有审阅人和结论；若仅有编码者自检，如实说明，不替代成同伴评审 |
| 相关构建和自动化检查通过 | 记录命令、结果和 GitHub Actions 运行链接，未建 CI 时不标为通过 |
| 数据与来源保持一致 | 页码正确、题目历史不被改写、删除和重试不产生孤立或重复数据 |
| 文档和过程记录同步 | 需求、必要的启动配置、AI 使用、测试记录及看板及时更新 |
| 重要成果已纳入版本管理 | 提交可追溯；里程碑提交和标签已推送远程 |

只有文档改动时执行内容、链接和 Git 检查，不为其制造业务功能测试结果。业务故事缺失必要验收证据时不能标为完成。

## 2 测试策略

后端测试重点覆盖访问归属、任务幂等、判分、事务和统计口径；接口与数据库集成验证真实持久化及约束。前端重点验证上传状态、阅读切页、AI 上下文、保存提示和练习交互。以少量端到端用例覆盖完整学习流程，避免把每个样式改动都转成重复测试。

AI 接入使用固定响应和模拟故障验证解析、限流、超时及引用检查，再对少量真实材料进行付费调用验证。结构合法和来源存在不代表事实正确，人工核对代表性答案与题目，并记录错误。未测量前不设定或宣称准确率。

课件样本包含短文档、长文档、图片、表格、公式、隐藏页、损坏文件和伪扩展名文件。导入样本包含有答案、无答案、跨页题目和扫描件。样本身份、预期页面和授权来源随执行记录，不默认把老师课件或个人资料上传 GitHub。

首轮环境、转换、页序、检索与 AI 路线的具体步骤见[技术验证计划](technical-validation.md)。技术验证与业务验收分别留记录；当前业务验收尚未执行，技术验证的局部进展以该计划与实际执行记录为准。

不将报告模板中的示例覆盖率或性能测试内容作为硬性指标。性能先记录大课件耗时、资源和失败情况，需要并发目标时再提出可测要求。

## 4 执行记录模板

每次执行追加记录，不把用例设计日期当作执行日期。失败后修复和回归另留结果。

| 字段 | 填写内容 |
| --- | --- |
| 用例与故事 | TC 编号、PB 编号 |
| 执行日期和执行人 | 实际日期、真实姓名 |
| 环境与版本 | 设备、浏览器、后端版本、提交 SHA、配置摘要 |
| 样本及输入 | 可复现的样本标识和必要数据，排除敏感信息 |
| 实际步骤与预期 | 与用例差异一并记录 |
| 实际结果 | 通过、失败、阻塞或未执行，不留模糊完成表述 |
| 证据与缺陷 | CI 链接、截图、日志摘要、缺陷编号 |
| 回归 | 修复提交、新执行日期、复测结论 |

执行记录可用团队工具或仓库文档维护，报告中保留可访问的对应材料。

## 2 材料对应表

| 阶段 | 必须留下的实际内容 | 报告位置与存放建议 |

| Sprint 1 回顾 | 做得好、不足、改进项、行动负责人和验证方式 | 报告 2.2.6；改进行动进入下一轮 |

| 最终总结 | Scrum、协作、自管理、AI 效果与风险、人工验证和改进建议 | 报告 5；结合真实问题和数据填写 |
| 最终提交 | 希冀平台提交终稿，更新个人贡献，准备可演示版本和项目工具数据 | 最终交付，不以 Git 提交代替平台提交 |

正式报告截图按 `docs/evidence/sprint-1/`、`docs/evidence/sprint-2/` 分类，执行记录按 `docs/records/` 分类。已有[初始增量执行记录](records/initial-increment-20261027.md)与后续记录；首轮目录已归档经检查的合成首页和脱敏回归统计，其余界面截图仍在 Git 忽略的 `.runtime/screenshots/`。尚无已归档的团队会议、看板和燃尽图记录，不创建假证据；后续选图经核验归档，隐藏Key及个人隐私。

评审快照不能用事后重画的曲线替代。Git 能记录代码演进，但不能替代看板、燃尽图和团队会议记录。报告模板第二轮中的部分标题误写 Sprint 1，正式填写时按实际第二轮改正。

## 8 报告持续更新

当前先以仓库文档保存需求、计划和模板。后续根据真实结果逐步填入课程提供的 Word 报告，不创建“全部完成”的预填终稿。AI-01 至 AI-10 是场景分类，模板明确不要求全部使用；未使用留空，实际使用则逐次记录。

个人贡献以真实 PB、提交、评审、测试、看板操作和文档记录为依据。主要编码者之外的成员可以承担真实的需求核验、测试、资料准备和过程管理工作，不以平均分配数字代替事实。

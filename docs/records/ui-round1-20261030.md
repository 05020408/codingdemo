# 第一轮界面优化执行记录

实际日期：2026 年 10 月 30 日（北京时间）。开发分支：`feature/ui-round1`；版本：`v0.4.1`。用户直接指令为“开始第一轮优化”，承接课程首页、课程详情和课件列表的界面规划。执行者为 Codex；用户为主要编码负责人，姓名及团队人工审阅待真实补充。

## 1 范围与结果

这是既有课程管理与课件阅读流程的后续优化，不回填为 Sprint 1 原始交付或团队评审。涉及 PB02 课程管理、PB03/PB04 课件处理展示及相应验证。

| 区域 | 实际变化 |
| --- | --- |
| 公共框架 | 统一图标、按钮、留白、纸面与蓝色基调；面包屑显示当前区域；新增加载、空列表、无匹配和错误状态 |
| 我的课程 | 标题与说明、搜索、新建入口；课程封面颜色按 ID 固定，不随排序变化；卡片进入课程，独立菜单负责编辑与删除 |
| 搜索与分页 | 按名称或备注匹配本人全部有效课程，每页 12 条；显式搜索/清空，地址保存 q/page；刷新与返回可恢复；删除或输入越界页码后调整到可用页 |
| 课程详情 | 课程名称、备注、真实创建/更新时间及管理入口；沿用课件、复习重点、答疑记录三个已实现入口 |
| 课件区 | 选择或拖入单份 PPTX，支持移除/重新选择；前端校验类型及 20 MiB 上限；先显示阅读、定位能力，再展开各处理阶段与错误 |
| 操作反馈 | 上传显示真实忙碌状态，不虚构上传百分比；只在后端允许时重试；菜单 Escape 关闭及焦点恢复；删除仍需完整名称确认 |

保留既有课件阅读、重点定位和 AI 答疑。未增加笔记、三种习题来源、阅读器重设计或逐字流式回答；本轮没有调用 DeepSeek。

## 2 代码与接口边界

前端新增 `AppIcon`、`CourseActions`、课程展示工具与独立课程样式；首页和详情共用编辑、删除行为。删除保留版本校验、幂等键与后端异步清理机制。课程和课件读取保留过期请求保护，不把上一课程的响应展示到新课程。

`GET /api/courses` 新增可选参数 `q`，默认空字符串；去掉首尾空白后最多 100 个 Unicode 码点。名称和备注任一包含即可匹配，`%`、`_` 按普通字符处理，不是通配符；只搜索当前用户的 ACTIVE 课程，列表和 total 使用同一过滤条件，按更新时间倒序、ID 倒序排列。原有不带 q 的调用保持可用。

服务端使用绑定参数，没有字符串拼接查询输入；新增集成用例覆盖跨页总数、备注、特殊字符、越权隔离、注入文本、超长输入及删除后不可搜索。没有数据库迁移或新依赖；本机原生 MySQL、Java、LibreOffice，未使用 Docker。前后端包与健康接口版本同步为 0.4.1。

首次全量运行实际为 47 项、1 项失败：新增搜索测试删除课程后遗留 QUEUED 清理任务，随后既有测试的 `processNext` 处理到了该任务，使它自己的任务仍为 QUEUED。修正新用例，在结束前按自己的任务 ID 确认清理完成，再全量运行得到上述通过结果。此处是测试数据隔离问题，不将其写成线上产品故障，也不删除首次失败证据。

原始日志仅本机保留于忽略目录 `.runtime/verify-ui-round1-initial.log`、`.runtime/verify-ui-round1.log`；归档[脱敏统计](../evidence/ui-round1/verification-summary.json)只摘录必要结果及 SHA-256，不复制可能包含环境信息的 Surefire XML properties。前端构建、截图及统计对应本轮源文件；完整提交号以本记录 Git 历史和 v0.4.1 标签为准，不在提交前编造 SHA。

## 4 浏览器核验

使用本机独立合成账户和自制 5 页 `mapping-fixture.pptx`；没有上传教师课件或真实学生信息。通过正式页面与接口操作，未将数据库写入作为界面验收。

1. 登录后的空首页、新建三门合成课程及自动展示。
2. 搜索备注中的“敏捷”返回 1 门，刷新保留查询；无匹配显示独立空状态；清空恢复 3 门。
3. 从课程卡片编辑名称/备注，更新排序后颜色保持；管理菜单 Enter 打开、Escape 关闭并恢复焦点；删除框名称不匹配时按钮禁用，随后取消。浏览器未执行真正删除，删除一致性由集成测试覆盖。
4. 文件选择器选择非 PPTX，显示原因并禁用上传；选择自制 PPTX，经历处理并到达“阅读与定位已就绪”。
5. 打开阅读器，翻到第 2 页、切换 AI 面板、显示第 2 页上下文和 AI 关闭提示；未提交 AI 问题，也未进行付费调用。
6. 切换复习重点及答疑记录，空状态可用。桌面 1280×900，以及 390×844、320×800 窄屏核验；320 视口下首页、课程、重点与阅读器文档宽度均为 305/305（client/scroll），没有横向溢出。
7. 最终浏览器 warn/error 日志查询返回空数组。已保存并逐张查看四张[界面截图](../evidence/ui-round1/README.md)。

## 5 限制与后续

实际上传验证采用文件选择器，未直接模拟拖放手势；未做本轮网络中断注入、多浏览器矩阵、完整无障碍/对比度审计。当前本地预览的 AI 开关关闭，不将上述阅读器检查当作真实模型回答验证。既有 AI 行为的历史证据保持在原记录中。

本轮自动化与代理浏览器自检不代表团队人工评审或整个 Sprint 验收。GitHub 推送后会按已有工作流触发 CI，本地通过不能替代远程 CI 结果；如需引用远程成功，另核实运行结果。界面后续可继续优化阅读器、重点列表和对话，但应单独形成范围与记录。

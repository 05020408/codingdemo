# 摘要篇幅校验与状态提示修复（2026-11-09）

用户在取消摘要token预算后再次提供失败截图，v2显示“摘要结构、长度或来源校验失败”。本次承接其“不要限制token长度”的要求处理残留篇幅校验，以300e587为基线；Java/Vue/原生MySQL，无Docker，保持deepseek-flash、应用0.4.4，不移动稳定标签。

## 观察与根因范围

只读任务/审计：来源145页、0页无文字，v2第一PART完成了3364个输出tokens，经过服务端正常结束检查后被SummaryContent.validate拒绝，其余两段与FINAL仍等待。v1曾输出恰好1800；第二次超过1800，说明先前请求参数移除已起效。

旧验证仍限制PART序列化结构3000字符、FINAL结构9000字符、Markdown和人工编辑12000字符，此外标题200、限制2000、主题20、单主题来源30、清单20及项目1000等规则均可能拒绝结构和来源正确的内容。这些限制与用户期望不符。旧响应未留存，不能确认这次具体触发字符、数量、格式还是来源规则；3364 tokens不是3364字符，也不能直接据此确定长度超限。明确修复了可复现的残留规则，不能声称还原了原响应或保证真实145页课件已成功。

## 实施

- 摘要验证取消编辑性篇幅/数量规则，只要求完整合法JSON、必需字段类型、非空标题/概述/主题正文、正确清单与真实来源；拒绝尾随额外JSON。
- 每条来源先校验，再按顺序合并合法重复ID；未知或非文本来源依旧拒绝，重复条目不能掩盖伪造内容。
- 错误具体说明JSON、字段、主题或未提供页面，不回显AI原文。没有自动修补或接受伪造出处。
- PART与FINAL提示词取消3000/9000字符要求，保持不传max_tokens，摘要审计升级summary-v2。阅读及定位参数保持既有值。
- Markdown生成不再设12000字符上限；人工编辑和textarea不截断长正文，仅保留非空与数据库MEDIUMTEXT的16777215字节容量校验。没有数据库迁移。
- 保留单段输入10000、最多12段、AI响应体256KiB、超时/租约、额度、幂等、来源变化与取消保护。摘要作为答疑背景仍受整次60000 UTF-16单元预算限制，超限拒绝且不静默截断。
- 页面将任务提交/继续/停止/编辑/采用分别提示，所选版本FAILED时隐藏残留成功色通知。元数据“覆盖”改“来源”，不冒充生成完成。

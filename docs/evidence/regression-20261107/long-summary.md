# 软件测试与交付的核心实践

## 整体概述

材料围绕需求、测试设计、集成与交付四个主题循环展开，强调以可观察行为、明确预期结果和可追溯证据支撑测试与验收。需求应描述可观察行为、有效输入、约束与验收标准，并消除歧义、建立测试与规则的追溯；测试设计用边界值分析与等价类划分组织有效和无效输入，并明确预期结果；集成测试关注组件契约、持久化与事务边界，以及重复提交、归属、并发和超时未知态；交付环节通过持续集成执行可重复检查，保留版本化证据、限制与回滚信息，自动化检查不替代人工验收。各主题均配有案例检查正常、无效、重复输入与保存状态，并要求解释规则、给出反例并注明来源。

## 需求与可追溯性

需求应描述可观察行为、有效输入、约束和验收标准；对含糊术语需与利益相关方复核，并将每个测试追溯到已陈述的规则。无效输入必须产生清晰错误且不改变已有记录。案例要求独立检查正常输入、无效输入、重复输入和保存状态，记录预期与实际结果，并通过解释规则、给出一个反例并注明来源进行复核。

## 测试设计方法

边界值分析选取上下限及其邻近值；等价类划分把预期行为相同的输入归组，并同时使用有效类和无效类。预期结果须明确写出，避免把单个示例当作完整覆盖。案例同样检查正常、无效、重复输入与保存状态，记录预期和实际结果，并以规则解释、反例和来源复核。

## 交付与持续集成

持续集成为每次变更运行可重复检查，测试样本保持合成数据。发布前复核失败，保留版本化证据、限制和回滚信息。自动化检查支持评审但不替代人工验收。案例独立检查正常、无效、重复输入与保存状态，记录预期和实际结果，并解释规则、给出反例并注明来源。

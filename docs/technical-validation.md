日期：2026 年 10 月 27 日。以下 TV01 至 TV06 是完整技术验证计划。当前工程已初始化，TV01 的构建、数据库及局部 TV02/TV03 已执行，见[本轮记录](records/initial-increment-20261027.md)。DeepSeek 一次基础连接见[独立记录](records/deepseek-connectivity-20261027.md)。TV02/TV03 的剩余故障与发布校验、TV04、完整 TV05、TV06 仍待执行。

## 1 验证顺序与产出

顺序为 TV01 环境 → TV02 提取与转换 → TV03 页码映射 → TV04 检索 → TV05 AI 接入；TV06 图片答疑后置，属于 PB21。优先验证最可能推翻后续设计的环节，发现失败先缩小并明确支持范围，不把失败样例从报告中隐藏。

每项验证产出真实执行记录、样本标识、实际环境和版本、结果及限制。现有[验收用例](quality-and-acceptance.md)用于业务验收，TV 用于技术路线验证，二者不能互相替代。

## 3 课件与页码验证

### TV02 逐页提取与静态转换

计划选取工作区中的《0 课程简介.pptx》和《第三章_软件开发过程_敏捷过程.pptx》作为短、长课件样本；实际执行时核对文件名和校验和。另准备自制的表格、公式、组合形状、图片和损坏文件样本，不把第三方课件复制进 GitHub。

1. 用已选 Java 库获取页序、标题、文字、表格和隐藏属性，记录缺失与阅读顺序问题。
2. 在独立目录和转换配置下生成 PDF，检查字体替换、布局、图表和特殊符号。
3. 顺序渲染图片与缩略图，记录耗时、峰值资源或可获得的资源观察值。
4. 测试超时、损坏文件、解压限额和工作目录清理；确认未影响其他用户程序。
5. 验证正文不足仍可预览；预览失败时原件下载或文字能力不被误报失效。

通过条件：代表性样本可读，限制如实说明；未达到质量要求的版式不称为完整保真。产出实际支持格式和可配置资源上限，关联 TC05 至 TC10。

### TV03 原页序与来源映射

自制至少包含普通页、隐藏页、空白页、重复内容页和纯图片页的样本，在页面中放置可辨认的原始编号。具体页数按样本实际记录，不提前填写结果。

1. 分别记录原 PPT 有序页号、内部 slideId、PDF 页号及图片文件。
2. 开启隐藏页导出，关闭备注页输出，核对总页数及逐页编号。
3. 在真实短课件上逐页核对；长课件检查全量页数和程序可验证顺序，并人工抽查开头、中部、结尾、隐藏页和特殊页。
4. 对每个来源跳转核验实际页面，重试处理后确认 slideId 未变化。
5. 主动模拟首次处理漏页或顺序错误，确认 mappingStatus=FAILED 且不发布错位预览；另测已有成功预览后重试失败，旧 VERIFIED 映射仍可用，新错误只记录在失败尝试中。

通过条件：自制样本所有页对应正确，真实样本未发现错位，异常被阻止发布；记录抽查范围，不能声称人工看过所有真实课件页面。关联 TC08、TC11、TC13。

## 4 检索与 AI 验证

### TV04 课程内重点检索

人工从真实课件标注一组明确重点和相关页，补充同义表述、跨多页、无匹配、只有图片及跨课程同名内容。标注人与标注日期实际填写，不由 AI 输出自动充当地面真值。

先运行不依赖 AI 的基础检索，再按需对比 AI 排序。记录每条输入、预期页、实际前几条候选、返回依据及耗时；汇总仅使用实际样本数量，不预设准确率。

通过条件：已标注核心示例能找到对应原页；无匹配和未就绪可区分；未授权课程与已删除页面不出现；人工确认和排除不被重新定位覆盖。若遗漏较多，先检查文字提取、分段和分词，再考虑更复杂检索。关联 TC13 至 TC15、TC32。

### TV05 DeepSeek 接入

当前进展：基础文本请求返回 HTTP 200 和 `OK`，实际总用量 10 tokens；仅基础连接子项已验证，以下结构化、故障与集成场景仍待执行。详见[基础连接记录](records/deepseek-connectivity-20261027.md)。

先使用固定响应与模拟错误：合法 JSON、空内容、截断、重复 slideId、非候选 ID、非法来源、超时、429、认证失败和服务不可用。检查结构验证、错误映射、额度预占、幂等重放及不确定请求记录。

实际 Key 与额度配置后，仅对少量非敏感文本和获准材料进行真实调用。核对当前模型名、thinking 参数、JSON 输出、用量返回及后续流式能力，不依赖默认值或旧模型别名。真实调用记录脱敏，不在仓库保存凭据。

通过条件：后端成功与异常均可控；非法来源不能入库；失败时无重复业务结果；没有 Key 时非 AI 流程可用。真实题目和解释另外进行语义核对，不能凭 HTTP 200 或 JSON 可解析宣称回答正确。关联 TC14、TC17、TC18、TC23 中适用于首轮的部分。

### TV06 当前页图片答疑

属于后续增强，在 PB09 基础稳定后验证实际模型图像能力、请求大小、当前页来源与回答。对同一图表分别做“实际发图”和“仅发文字”请求，核对界面上下文与回答声明是否一致。未验证前不启用图像理解入口，结果不阻断首轮交付。关联 TC34。

## 5 持久化与故障窗口

| 场景 | 验证重点 | 相关验收 |
| --- | --- | --- |
| 原件已移动但数据库未提交 | 能发现并清理孤立文件，不展示成功课件 | TC05、TC07 |
| 处理执行中服务重启 | 过期租约可识别，旧工作者不能晚发布 | TC10 |
| 索引写入与数据库确认之间崩溃 | 回查版本和重建保证无旧结果冒充成功 | TC13、TC32 |
| AI 请求已发出后超时 | 记录 UNKNOWN 与额度，不无条件重发 | TC14、TC17 |
| 编辑重点时旧定位返回 | 旧任务取消，不覆盖新内容和人工操作 | TC12、TC15 |
| 删除课件或课程时处理完成 | 生命周期检查拒绝回写，清理任务仍能运行 | TC32、TC33 |
| 两个相同请求并发 | 同键不会创建重复课件、重点或付费任务 | TC05、TC10 |

以上同样为未执行故障验证，不因设计写明处理方法就算已修复。

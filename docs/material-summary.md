# 课件核心摘要

初始确认日期：2026-11-04；当前流程更新：2026-11-09（北京时间）。本增量在现有逐页文字、原页来源和阅读答疑上增加可编辑、下载的整份课件摘要。后端 Java/Spring Boot，前端 Vue 3，DeepSeek API，本机原生运行，无 Docker。

## 行为约定

- 学生主动生成；短课件一次成文，长课件按文字预算分段理解、统一提纲、分别撰写主题，最后由程序按提纲合成一份 MD。分段结果不作为完整摘要展示，也不再要求 AI 一次输出长篇最终全文。
- 依据全部已提取文字（含隐藏页），无文字页只记录覆盖限制，不伪装完成OCR。生成不依赖预览或索引。
- 摘要保留概述、主题内容、复习清单和来源页；不得添加未经材料支持的“必考”结论。来源存在校验不代表语义正确。
- 正文存数据库，按需导出UTF-8 Markdown；生成、人工编辑均产生版本。生成失败不影响旧版，后台完成不覆盖并发人工修改。
- 答疑选项“附带本课件核心摘要”默认关闭；发送时固定具体版本和完整正文。摘要只作背景，原文引文仍须在本次提供的页面中验证。
- 摘要正文不再设置12000字符篇幅上限，编辑器也不裁切长摘要。保留MEDIUMTEXT存储容量和AI响应体保护；页面正文、有限历史、摘要合计60000个UTF-16单元，超限明确拒绝，不静默截断摘要。

## 任务与数据

### 当前长课件流程（2026-11-09）

1. **PART 分段理解**：按提取文字量动态分成多段，不固定两段。普通页面尽量整页保留，超长页优先在预算后半部的换行处分开；完整保留文字及页面标识。当前没有按章节语义识别分段。
2. **OUTLINE 统一提纲**：把成功的分段整理结果交给 AI，合并相近知识，确定主题顺序、写作要点、整体概述、复习清单及限制。提纲不展开整篇正文。
3. **TOPIC 逐主题撰写**：每次只发送一个主题的写作要点、相关分段内容及整体提纲标题/概述。要求统一术语、减少重复，返回该主题正文和来源；标题必须与提纲一致，来源只能来自本主题允许页面。每个主题各自保存。
4. **ASSEMBLE 本地合成**：所有主题成功后，由程序拼入标题、概述、按顺序的正文、复习清单、限制及原页链接，保存为一个成功版本。此步不调用 AI、不消耗调用额度。MD 编辑、下载、版本切换及可选附带答疑保持原行为。

若有 N 个输入分段、提纲产生 K 个主题，实际 AI 请求为 **N+1+K**，另有一次本地合成步骤。开始前只知道至少 N+2 次，界面明确标为“至少”；提纲生成后更新主题数、总步骤及剩余请求。默认不设账号每日请求次数限制；只有显式配置正整数日限额时，额度不足才停在未完成步骤并保留进度，预检不预留额度。恢复时只需下一次AI请求可用；若仅剩本地合成，AI关闭也可恢复。

V7 只新增版本 workflow 和步骤 phase 字段；既有版本默认为 LEGACY，不改写正文。旧长任务若所有 PART 已成功、FINAL 失败或已停止，学生主动点击继续时升级为 OUTLINE/TOPIC/ASSEMBLE，并复用原 PART。此类恢复至少新增两次 AI 请求，具体由提纲主题数决定；不再仅重做一次 FINAL。尚有未完成 PART 的旧任务沿用原流程；已成功旧摘要照常查看。没有后台自动升级、自动重发或重新计费。

每一步仍校验来源指纹、任务租约、课件归属、取消状态和并发版本。新 OUTLINE/TOPIC 使用 summary-v3 提示词审计，既有 PART/短课件 FINAL 保持 summary-v2。完整性校验失败或 provider 返回 length 时不发布部分摘要，用户主动恢复。拆分降低单次长输出风险，但不能保证服务永不截断，也不能保证内容无遗漏或跨主题完全无重复。[本次实现与验证](records/thematic-summary-20261109.md)。

### 历史演进与仍适用的边界

新增V6：material_summaries（当前采用版本与并发版本）、material_summary_versions（来源、正文、生成/人工版本）、material_summary_parts（持久分段/汇总进度），chat_turns增加摘要快照。

单段输入预算10000个UTF-16单元、最多12段，超过预算拒绝并说明；超长页面按段切分且保留同一页面标识。每步独立async_jobs任务和AI审计，按实际请求保留调用审计；日请求次数默认不限。显式启用正整数日限额时按实际尝试共享计数，中途耗尽可次日主动恢复，已成功分段复用。

2026-11-08按用户“不要限制token长度”的要求，摘要PART及FINAL请求不再传max_tokens，移除原1800/5500 token应用上限，采用DeepSeek服务端默认输出预算，并非无限输出。当日保留的字符规则由下一次修复撤销，历史范围见[执行记录](records/summary-token-default-20261108.md)。服务端finish_reason=length时明确报AI_OUTPUT_TRUNCATED并保留实际用量，不发布不完整正文、不自动付费重试。

2026-11-09继续修复：取消PART/FINAL提示词及验证中的3000/9000字符、最终Markdown和编辑的12000字符限制，取消主题/清单/合法来源数量及各字段的编辑性上限。仍要求完整JSON、必需文本与非空主题、清单类型、每个主题真实来源；重复的合法来源规范为一项，逐项验证后才去重，伪造来源仍拒绝。错误说明具体字段、主题或来源原因，不回显课件正文或原始响应。摘要提示词审计升级summary-v2；阅读和定位请求参数不变。人工编辑仅检查非空与MEDIUMTEXT的16777215字节存储容量，AI响应仍有256KiB传输保护，既有输入分段、超时和共享额度不变。任务提交/恢复提示与生成成功分开，版本页数标为“来源”而非已完成“覆盖”。见[执行记录](records/summary-validation-20261109.md)。

同日早先发现：省略max_tokens仍受DeepSeek非思考模式默认8K影响，145页材料3段成功后FINAL在8192截断。因此摘要请求显式采用官方允许的最大输出预算393216（384K），不要求生成到该长度；前述“不传参数”与256KiB为历史状态。摘要接收容量改为8MiB、单次等待10分钟，心跳和取消检查保留；阅读答疑保持2400 token参数、256KiB及60秒。该次修复尚沿用最终汇总及summary-v2，之后由上述多阶段流程取代新长任务的FINAL。提供商最大值有限，输入/存储/答疑上下文等边界仍在。[官方参数说明](https://api-docs.deepseek.com/api/create-chat-completion/)及[历史执行记录](records/summary-final-budget-20261109.md)。

任务租约90秒、心跳10秒，外部调用不持有业务事务。每步最多一次外部尝试；失败/未知不自动重发。取消、来源改变、删除或租约失效后不可发布；服务重启将过期工作标为中断，用户主动恢复。新任务标识用于显式重试。

版本保存完整页面来源指纹；生成发布前和附带答疑前检查。重命名不使摘要过期，文字/页面/生命周期变化使其过期。学生可在明确提醒后仍选择已有成功版本作为背景；重试固定旧快照。删除课件清理摘要、分段正文和问答摘要正文副本；课程删除同时清理所有相关记录。问答保留已完成回答和必要版本来源说明。

## 接口

所有接口检查账号、课程与课件归属。写接口沿用CSRF、Idempotency-Key及expectedVersion并发控制。

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/materials/{id}/summary | 当前摘要、版本、进度、预计请求数、额度及提取限制 |
| POST /api/materials/{id}/summary-generations | 主动生成，幂等返回版本标识 |
| POST /api/summary-generations/{id}/cancel | 停止后续步骤并丢弃迟到结果 |
| POST /api/summary-generations/{id}/retry | 主动恢复未成功步骤 |
| GET /api/summary-versions/{id} | 查看正文与来源 |
| POST /api/materials/{id}/summary-versions | 保存人工修改为新版并采用 |
| PUT /api/materials/{id}/summary/current | 采用指定成功版本 |
| GET /api/summary-versions/{id}/download | 下载Markdown |

原答疑POST turns增加可选summaryVersionId；历史返回版本号、来源类型、过期/不可用信息，不返回内部提示词或快照正文。

## 验证与交付

替身验证短/长课件、覆盖与汇总、非法来源、失败恢复、共享额度、幂等、并发编辑、取消、租约、删除竞态及摘要快照。浏览器检查桌面/窄屏、编辑离开提醒、安全文本渲染、下载和可选发送。真实AI仅用自制材料单独记录，不以替身结果声称真实总结质量。执行日志、失败、实际测试数量及Git同步情况写入本增量执行记录，不回填历史Sprint测试。

## 收尾顺序

1. 核对交付清单、首轮版本和团队信息，确定待补测项。
2. 在可复现环境中执行适用验收，记录实际日期、人员、提交和结果；旧数据库不降级迁移。
3. 审阅代码与文档，处理阻断问题，补齐真实平台数据。
4. 进行约 10—15 分钟评审，保存当时看板与燃尽图、反馈及范围调整。
5. 进行回顾，将确认的改进行动及负责人纳入 Sprint 2。
6. 汇入 Word 阶段报告、更新 AI 日志和贡献依据，经团队确认后关闭迭代。

本轮整理不新增业务功能，不重跑 Maven、前端构建或付费 AI 调用；历史测试结果保留原执行日期。本轮检查的是范围、引用、数字、证据和 Git 差异。文档提交属于收尾材料版本，不改变 `v0.3.0`、`v0.4.0` 标签，也不宣布 Sprint 正式验收通过。
